# Agentic OS: план доведения продукта до production

Актуально на 28 июля 2026 года. Этот документ описывает реальное состояние,
очередность работ и критерии завершения. Секреты и учётные данные здесь не
хранятся.

## Этап 1. Единый web/mobile аккаунт — завершён

- Вход по email и паролю создаёт сессии Agentic OS и MILA.
- Одноразовый код из веб-панели передаёт короткоживущий pairing grant.
- Мобильное приложение обменивает grant на отдельный 30-дневный токен Agentic OS.
- Pairing grant нельзя использовать повторно.
- MILA-сессии имеют срок жизни 30 дней и очищаются автоматически.
- Технические сессии dashboard отзываются при создании новой.
- Android release использует только HTTPS; debug/profile могут работать по HTTP.
- Серверные `.env`, SQLite и резервные копии закрыты правами `600/700`.

Основные файлы:

- `server/lib/auth.js`
- `server/routes/integrations.js`
- `server/lib/mila.js`
- Mobile repo: `backend/db.mjs`, `backend/server.mjs`
- Mobile repo: `lib/services/auth/mila_account_service.dart`

## Этап 2. Полноценный жизненный цикл аккаунта

1. Добавить подтверждение email и безопасное восстановление пароля.
   **Код готов:** одноразовые HMAC-хешированные токены, SMTP-доставка,
   web/mobile блокировка неподтверждённого входа, повторная отправка и отзыв
   всех сессий после сброса. **Эксплуатационный шаг:** указать SMTP в серверном
   `.env`, проверить доставку и включить `EMAIL_VERIFICATION_REQUIRED=true`.
2. Добавить список пользовательских сессий с отзывом отдельного устройства.
   **Готово:** web login, mobile login и MILA pairing создают независимые
   серверные сессии; пользователь видит свои устройства в Settings и может
   завершить одно устройство либо все остальные. Токены в реестре не хранятся,
   а удаление аккаунта очищает его сессии.
3. Добавить смену пароля, удаление аккаунта и экспорт личных данных.
4. Добавить MFA для Creator/Admin.
5. Провести production-тест отдельного пользователя Member в web и Android.
6. Подготовить миграцию `users.json` и персональных данных в PostgreSQL.

Готово, когда новый пользователь самостоятельно регистрируется, подтверждает
email, входит в web и Android, видит только свои задачи/заметки/SOUL и может
закрыть все свои сессии.

## Этап 3. Реальные системные функции вместо демо

1. Перенести Guardrails из browser storage в защищённый API. **Готово:** экран
   показывает только реально действующие серверные, RBAC и Hermes-защиты.
2. Сделать Secrets интерфейсом метаданных секретов без возврата значений в UI.
   **Готово:** значения шифруются AES-256-GCM и после записи не возвращаются.
3. Подключить Evaluations к реальным запускам агентов и результатам проверок.
   **Готово:** live Four C evaluation проверяет production-сервисы и сохраняет
   историю результатов.
4. Перенести оставшиеся локальные Memory-настройки на пользователя сервера.
   **Готово:** вкладка Memory читает SOUL/onboarding, личные заметки и аудит
   обращений к Obsidian через персональный `/api/memory`; фиктивные browser
   entries, vectors и recall rate удалены.
5. Добавить audit log для изменений ролей, секретов, guardrails и заданий.
   **Готово:** изменения аккаунтов и ролей, секреты, evaluation runs, настройки
   оркестрации и мутации Kanban пишутся в защищённый governance audit, который
   отображается на экране Guardrails.

Основные зоны:

- `assets/js/pages/misc.js`
- `server/routes/`
- `server/store.js`

2. Довести пользовательский dashboard: briefing, задачи, заметки, календарь,

3. Подключить Personal Calendar/Inbox к реальному Google Workspace статусу.
4. Показывать понятное состояние `не подключено`, а не фиктивные данные.
5. Синхронизировать изменения web/mobile через сервер, не через localStorage.

## Этап 5. Полный RU/EN/UZ — завершён

1. Убрать hardcoded English из Member, Kanban, Settings и misc-экранов.
2. Перенести строки в `assets/js/i18n.js`.
3. Добавить автоматический тест отсутствующих ключей для всех трёх языков.
4. Проверить переполнение элементов на desktop и Android.

Member, Personal, Kanban, Settings, Memory, Guardrails, Secrets, Evaluations,
Observability, Integrations и MCP используют общий словарь RU/EN/UZ. Тест
автоматически собирает используемые ключи продуктовых экранов и не допускает
отсутствующий перевод. Выбранный язык сохраняется в серверном профиле и
применяется в web и MILA.

Готово, когда переключение языка меняет весь текущий экран без перезагрузки и
нет смешения языков кроме пользовательского контента.

## Этап 6. Интеграции и эксплуатация

1. Повторно авторизовать Claude Workspace и добавить раннее предупреждение об
   истечении OAuth.
2. Расширить Google OAuth scopes только для реально включаемых функций.
3. Добавить ежедневную проверку Agentic OS, MILA, LiveKit, Hermes, Obsidian и
   резервных копий.
4. Добавить staging перед production и обязательный smoke test после deploy.
5. Подключить метрики задержки voice-to-voice, ошибок STT и завершения turn.
