# Один цельный Agentic OS вокруг командного центра — мастер-план

*2026-08-26. Продолжение `AGENT_OS_UPGRADE_PLAN_RU.md`: командный центр (#/command) и карта «Второй мозг» (#/command/map) уже построены по образцу RUBRIC Agentic OS (RoboNuggets). Этот план — про следующий шаг: не «красивая дверь перед старым домом», а перестройка самого дома.*

## Принципы

1. **Не мосты, а структура.** Кольцо, ядро и панели не «ссылаются на старые страницы» — они и есть интерфейс. Старые страницы либо втягиваются в стейдж (листы-оверлеи), либо перекрашиваются в командный язык, либо расформировываются.
2. **Данные вперёд.** Каждый пиксель стейджа обязан отвечать на вопрос «какие живые данные за тобой стоят?». Галактика — это настоящие объекты второго мозга, а не украшение.
3. **Каждая фаза — рабочий релиз.** `npm test` зелёный, версия поднята, deploy.sh с гейтом. Никаких «переходных» состояний в проде.
4. **Контракты дома соблюдаются всегда:** шрифт ≥12px, vh+svh парами, каждый `var(--x)` определён в CSS, каждый i18n-ключ в трёх языках, версия поднята при касании assets/server.

## Целевая архитектура

```
Стейдж (#/command) — оболочка ОС
├─ Кольцо: модули с живыми бейджами (счётчики, статусы)
├─ Ядро: галактика = объекты второго мозга; поиск по ВСЕМУ (Ф1)
├─ Панели: календарь · входящие · колода навыков · регламенты · бизнес
├─ Листы (cmd-sheet): лёгкие модули открываются поверх стейджа (Ф3)
└─ Карта (#/command/map): реальный граф хранилища + слои системы (Ф2)
Глубокие страницы (канбан, ERP, чат, Claude) — тот же язык дизайна (Ф5)
```

## Фаза 1 — Поиск второго мозга из ядра

**Цель:** строка в центре ищет по всему: заметки, задачи, миссии, регламенты, чаты, навыки, артефакты студии, память, ERP-модели.

Шаги:
1. `server/routes/brain.js` → `GET /api/brain/search?q=&limit=` — параллельная федерация уже существующих источников: `knowledge.search`, `messenger.search`, канбан-доска (заголовок/описание), missions, routines, `skills.list`, studio snapshot (design/media/generations), memory snapshot, ERP `find_models` (только `code` — остальные фильтры ERP молча игнорирует, это известная ловушка).
2. Ответ типизирован: `{results: [{type, id, title, snippet, route, at}], sources: [{name, ok, partial}]}`. Отказ одного источника не роняет ответ — и ответ **говорит**, что он неполный (домашнее правило из ERP MCP).
3. Клиент: у центральной строки два режима — фильтр кольца (есть) и Enter → поиск мозга. Результаты группами по типу вокруг ядра, стрелки/Enter, клик — переход или предпросмотр заметки листом.
4. Тесты: слияние/частичность федерации; маршрут; i18n ×3.

**Приёмка:** запрос «милана» находит заметку, задачу и чат < 1.5 с; выключенный runtime не ломает поиск; в выдаче видно, какие источники ответили.

## Фаза 2 — Галактика и карта из настоящих данных

1. Галактика сеется из реальных счётчиков по доменам хранилища (папки vault через `knowledge.graph`/`notes`), цвета = домены карты; hover кластера → имя домена и счётчик; клик → карта с фокусом домена.
2. Карта: узлы и связи из `/api/knowledge/graph`; размер сектора ∝ числу заметок; клик по узлу → лист заметки (`knowledge.notes/read`); гнёзда регламентов подписаны реальными именами; бейджи хекс-чипов — живые статусы.
3. Легенда и счётчики — только настоящие числа.

**Приёмка:** новая заметка в vault меняет цифры и плотность на стейдже после обновления.

## Фаза 3 — Листы вместо переходов (cmd-sheet)

1. Компонент `cmd-sheet`: правый оверлей в языке стейджа (чёрный, hairline, ember), scrim, Esc, фокус-ловушка, deep-link `#/command/sheet/<name>`.
2. Первые листы: Входящие (полный needs-you), Сегодня (personal), Регламенты (управление: пауза/запуск), Заметка (предпросмотр + append), Навык (content + toggle).
3. Кольцо и панели открывают листы; глубокие страницы (канбан, ERP, Claude, чат, студия) пока остаются страницами.

**Приёмка:** типовые операции дня (одобрить, отложить, запустить регламент, прочитать заметку) не покидают стейдж.

## Фаза 4 — Слияние структуры

1. Командный центр становится домом оператора (`""` → command). Старый Обзор расформировывается: attention → лист Входящих, сервисы/хост/бэкап → лист «Системы» (LED-ы кликабельны), KPI → панели стейджа. `dashboard.js` удаляется, маршруты редиректят.
2. personal / my-tasks / my-notes у оператора складываются в лист «Сегодня» (для Member страницы остаются).
3. Рейл: шесть секций сохраняются (контракт console-shell.test.js), но дети чистятся от дублей; палитра ⌘K по-прежнему достаёт всё.

**Приёмка:** старые URL работают (редиректы), тест «every destination still has a home» зелёный, оператор попадает на стейдж.

## Фаза 5 — Язык дизайна на всю ОС

1. `tokens.css`: тема `command` (чёрный + ember) как третья, с добавкой контраст-пар в design-tokens.test.js — значения и тест меняются вместе, никогда порознь.
2. Оболочка (rail, topbar, палитра, MILA-орб) — в командном языке для оператора.
3. Перекраска страниц по частоте использования, по одной на релиз: Канбан → Регламенты → Знания → Чат → Флот (Агенты+Hermes+Claude) → ERP/Студия → остальное.
4. Роли Member/Design — решение владельца: остаются на светлой теме или тоже переходят.

**Приёмка:** ни одного экрана, где старый и новый язык встречаются в одном виде-порте.

## Фаза 6 — Настоящая колода навыков

1. Колода = `api.skills.list` (реальные /имена), включение/выключение, лист с содержимым навыка; поиск по hub.
2. ▶ на карточке запускает реальный путь: blueprint регламента или канбан-задача с навыком; выбор модель×усилие (как у RUBRIC) — если claude-code профили это реально поддерживают, иначе честно отложить.
3. Флот (агенты) — отдельная строка колоды: агент ≠ навык.

**Приёмка:** навык из колоды реально запускается и виден в регламентах/канбане.

## Фаза 7 — Бизнес-док и голос

1. ERP-панель на стейдже: живой срез (выработка, остатки) из `erp.snapshot` — у RUBRIC это «YOUTUBE STUDIO», у Milana это фабрика.
2. Analytics / Design / Media — листы поверх стейджа; Speech — лист записи.
3. MILA-орб на стейдже: голос из любой точки, вызов не прерывается навигацией (док уже умеет).

**Приёмка:** утренний вопрос владельца «что на фабрике?» отвечается, не уходя со стейджа.

## Фаза 8 — Полировка и закрепление

1. Telegram Mini App: safe areas, tabbar, производительность сцен (30fps, пауза в фоне).
2. A11y: фокус в листах, reduced-motion, контраст ember-пар.
3. Документация: OPERATIONAL_HOME.md переписывается под стейдж; RU/EN/UZ вычитка всех cmd-ключей.
4. Прод-прогон: полный E2E, замер веса страницы и времени первого кадра.

## Решения, которые нужны от владельца

1. **Когда стейдж становится домом** — в Фазе 4 (рекомендую) или сразу.
2. **Судьба старого Обзора** — расформировать (рекомендую) или оставить как лист «Ops».
3. **Тема ролей Member/Design** — светлая остаётся или командная для всех.
4. **ERP на стейдже** — вместо панели «Память» или рядом (третья панель слева).
5. **Порядок перекраски** в Фазе 5 — предложенный или другой.

## Порядок и ритм
