# План развития Milana Agentic OS

**Дата:** 2026-08-08.
**Источник идей:** YouTube-канал [Julian Goldie SEO](https://www.youtube.com/@JulianGoldieSEO) — серия про «Agent OS» / «Hermes Agent OS» / «Claude Agent OS». Разобраны транскрипты 8 ключевых видео (Hermes Agent OS, Hermes v0.20, Oracle, Muse, Agent OS Q&A ×2, Lead Machine, SEO Command Center).

## 1. Что у него на самом деле

У Голди это один продукт под разными заголовками: **дашборд-«command desk»** поверх открытого агента Hermes (Nous Research) + **Obsidian как общая память** + **кроны**. Продаётся как zip в его платном сообществе. Канал — маркетинговый конвейер (~20 видео в день), цифры «549k охвата» — его реклама. Но **паттерны внутри здравые**, и почти все ложатся на то, что у нас уже построено.

Его составные части:

| Его название | Суть | Есть ли у нас |
|---|---|---|
| Command desk | Один экран: чат, голос, канбан задач, менеджер моделей/скиллов/кронов, история сессий | ✅ в основном: SPA с chat, hermes, missions, routines, kanban (`server/lib/hermes-kanban.js`), agents, settings |
| Kanban job board | Тикет → диспетчер-триаж → воркеры строят автономно | ✅ прокси на Hermes-плагин; ⚠️ не связан с нашим флотом и памятью |
| Goal mode / Loop engineering | Цель + definition of done + N раундов + **отдельная модель-судья** решает «готово/не готово» | ❌ Missions есть, но без петли и судьи |
| Память (Obsidian) | Каждая сессия автоматически логируется дневной заметкой; все агенты и модели читают один vault; «memory galaxy» — граф | ⚠️ vault есть, `sharedAgentContext` есть; **обратной записи нет** — учебная петля объявлена и не реализована (`agentos-runtime/memory/index.json`) |

| /learn | Скормил папку/доку/страницу или «запомни, как я это сейчас сделал» → агент пишет **скилл** по шаблону (когда применять, шаги, типовые ошибки, как проверить); скилл дообновляется с каждым фидбеком | ⚠️ Skill Studio есть (`docs/SKILL_STUDIO.md`), автогенерации из демонстрации нет; у флота стоят стоковые скиллы (apple, smart-home, yuanbao) |

| Grounded citations | Каждое утверждение исследования подкреплено источником; режим факт-чека | ❌ (а у нас в плейбуке прямое правило «не выдумывать — спрашивать») |
| Approvals | Майнинг истории одобрений → предложение авто-одобрений; circuit breaker после серии отказов | ⚠️ governance.js есть, майнинга и предохранителя нет |
| Прочее | Webhooks наружу, A2A-протокол, context inspector, артефакты с live-preview, пиксельный «питомец»-индикатор, Tailscale с телефона | частично / не нужно |

## 2. Принцип отбора

Берём только то, что усиливает **оптово-производственный бизнес Milana Premium** (B2B, экспорт 20+ стран, min 1 бага) и закрывает наши текущие долги. Не берём: музыкального агента, «питомца», погоню за каждой новой моделью, мульти-сайтовый SEO-спам.

## 3. Фазы

### Фаза 0 — Фундамент (техдолг, ~1 неделя)
Прямо из [agentic-os-open-threads]:
1. **i18n дашборда** — `assets/js/pages/dashboard.js`: подключить словарь (1378 строк уже есть), убрать ~60 английских строк.
2. **Индикатор миграции БД на дашборде** — Postgres vs JSON-fallback, глубина outbox, refreshFailures (`server/lib/postgres-*`).
3. **Голосовые настройки — на сервер** (сейчас localStorage + настройки телефона врозь).
4. **Обрезать BASE_INSTRUCTIONS голосового агента** (3183 знака стиля, конфликтующего с профилем) — оставить только LiveKit-специфику.

### Фаза 1 — Замкнуть петлю памяти ✅ СДЕЛАНО 2026-08-12

Реализовано в `server/lib/journal.js`:
- Каждое действие, меняющее состояние (задача, заметка, напоминание, встреча, карточка
  Hermes, задача/уведомление в ERP, миссия), дописывает строку в
  `vault/Agentic OS/Journal/YYYY-MM-DD.md`. Дата — в часовом поясе пользователя.
- `sharedAgentContext` возвращает последние дни журнала агентам: лимит 1800 из 9000
  знаков, после фактов о компании, чтобы никогда их не вытеснить.
- Экран «Память» показывает журнал лентой, сгруппированной по дням.
- Чтения не пишутся, застейдженные действия не пишутся, недоступный vault не ломает
  действие пользователя.

Не сделано: **итоги рутин**. Они выполняются внутри Hermes, поэтому их перехват требует
опроса, которого пока нет. Миссии пишутся, рутины — нет.

<details><summary>Исходный план фазы</summary>
Сейчас у нас знание течёт только «вниз» (playbook → агент). Обратной записи нет — это и есть разрыв между нами и его системой.
1. **Дневной лог сессий в vault**: каждая сессия Hermes/Mila/миссия дописывает заметку `vault/Agentic OS/Journal/YYYY-MM-DD.md` (что делали, что решили, что вышло). Точка входа — `server/lib/sessions.js` + `knowledge.js`.
2. **Чтение журнала агентами**: последние N дней журнала — в `sharedAgentContext` (в остаток 9000-знакового бюджета, после фактов воркспейса; правило усечения из `server/lib/onboarding.js` сохраняем).
3. **Итоги миссий/рутин → память**: успешная рутина пишет результат («опубликовали X, отклик Y») туда же. Это включает его цикл «система умнеет каждый день».
4. **Экран «Память»** в SPA: что агент знает, откуда, когда обновлялось (у нас уже есть `readMemorySnapshot` в `server/lib/memory.js` — вывести его в UI, а не строить «галактику»).
</details>

### Фаза 2 — Бизнес-радары на Routines (~2–3 недели, можно по одному)
Всё это — рутины (`docs/ROUTINES.md`), а не новые подсистемы. У каждой: журнал истории по дням, карточки со счётом, кнопки «в 1 клик».
1. **Радар рынка («Oracle»)**: крон 24ч — новости текстиля/домашней одежды, рынки экспорта (СНГ, Ближний Восток…), тренды маркетплейсов → судья-скоринг по сигналам (релевантность аудитории, свежесть, соответствие ассортименту) → карточки идей → кнопки: «пост» / «статья» / «в Studio (Higgsfield) на видео/картинку». Итог дня — в vault-журнал.
2. **Монитор конкурентов («Astros»)**: ⚠️ блокер — реальные конкуренты не подтверждены владельцем (см. Marketing Playbook). Первая итерация: агент сам составляет список кандидатов и **спрашивает подтверждение**, не выдумывая.
3. **Контент-аналитик («Muse»)**: heat score наших публикаций (просмотры + скорость набора) → победители → «что делать дальше» с заголовками и хуками. ⚠️ Блокер: официальные соцаккаунты до сих пор не подтверждены — пока можно начать с сайта (GSC) и Telegram-канала, если он есть.
4. **Grounded citations как правило радаров**: каждая карточка идеи несёт ссылки-источники; факты о продукции — только из playbook/ERP, недостающее помечается «❔ спросить владельца». Это буквально наше правило из плейбука, возведённое в механизм.

### Фаза 3 — Машина лидов B2B (самая большая бизнес-ценность, ~3–4 недели)
Для оптовика с экспортом это важнее любого контента.
1. Вкладка **Leads**: ICP на естественном языке («оптовые закупщики домашней одежды в Казахстане, сети 10+ магазинов») → поиск и обогащение через Hunter/Snov/Apollo (выбрать по покрытию СНГ/Азии) → верификация email → скоринг 0–100 → пайплайн-сегменты: new / enriched / valid / contacted / replied.
2. **Персональный опенер** на RU/EN/UZ из памяти (факты фабрики: 3 фабрики, 1500 сотрудников, 25 лет, min 1 бага — уже верифицированы в playbook).
3. **Guardrails обязательны**: отправка только после ручного одобрения менеджером (у него это тоже есть: «check → approve → then send»); отдельный «песочный» ящик; лимиты отправки. Governance-слой уже есть — расширить.
4. Крон-режим: еженедельное пополнение воронки по сохранённым ICP.
5. Связка с ERP: ответившие лиды → карточка клиента.

### Фаза 4 — SEO-петля для milanapremium.uz (~2 недели)
1. Подключить **Google Search Console API**; striking distance: запросы с показами без кликов / низким CTR / позиции 8–20.
2. Генерация статьи с **уникальной фактурой из памяти** (производство, цифры, кейсы) — его «анти-слоп» правило; без выдуманных характеристик тканей (пока владелец не дал составы — «❔»).
3. Публикация на сайт + отправка на индексацию; **замер через 28 дней** кроном; результат — в память (что сработало → влияет на следующий цикл).

### Фаза 5 — Goal mode в Missions (~1–2 недели)
1. В `missions.js`/оркестраторе: поле **«критерий готовности»**, число раундов, **модель-судья**, отличная от исполнителя, решает «готово / ещё круг».
2. Circuit breaker: N неудачных раундов или отказов подряд → стоп и уведомление.
3. Push при завершении (push-инфраструктура уже есть — `server/lib/push-service.js`).

### Фаза 6 — /learn и скиллы под наш бизнес (~1–2 недели)
1. Команда **/learn** в чате Hermes: из папки/доки/URL или из только что показанной последовательности действий генерируется скилл по шаблону: описание → когда применять → шаги → типовые ошибки → как проверить. Складывать в Skill Studio.
2. Скилл **дообновляется при фидбеке** («в следующий раз контрастнее» → скилл перезаписан).
3. Заменить стоковые скиллы флота (apple/smart-home/yuanbao) на реальные: «оптовый прайс-ответ», «карточка товара маркетплейса», «экспортная документация», «бриф для Higgsfield-студии». Hermes (default) сейчас вообще без скиллов — начать с него.

### Фаза 7 — Голос Mila (~2 недели, аккуратно)
С учётом [mila-voice-architecture] — ничего не пере-выводить, всё уже промерено:
1. **Смена модели на native-audio** (`GEMINI_LIVE_MODEL`) — включает affective dialog и лучший контроль подачи. Осознанный размен: уходим с 3.1-live.
2. **Wake word на вебе** («Мила») + слово «стоп» — локально в браузере, без отправки звука до активации.
3. **Голосовые в Telegram** (для Узбекистана Telegram >> WhatsApp): войснот боту → транскрипция → ответ Mila текстом/аудио. Новый бот-мост в `services/`.
4. **Mid-turn redirect** в чате: короткая корректировка на лету без сброса работы.

### Фаза 8 — Платформа (фоном)
1. **Майнинг одобрений**: по истории governance предлагать список авто-одобряемых действий.
2. **Webhooks наружу** (подписанные события: сессии, завершения миссий, ошибки) — для интеграций и мониторинга.
3. **A2A между agentic-os и mila-agent** вместо самодельных связок.
4. **Context inspector**: что именно занимает контекст агента (у нас бюджет 9000 знаков — показать, что влезло, что усеклось).
5. **Мобильный доступ**: web уже есть за прокси; Tailscale не нужен.

## 3a. Сделано: персональный агент (2026-08-10)

Владелец выбрал это первым приоритетом, вне порядка фаз ниже.

- **Планировщик дня** (`server/lib/personal-planner.js`) — сводит календарь, открытые задачи, ожидающие подтверждения и флаги ERP в одну ленту: встречи, блоки фокуса в свободных окнах (час на срочное, 45 мин на обычное, обед не занимается), алерты по просрочкам, накладкам и тому, что не помещается в день. Работа не ставится раньше «сейчас» и раньше начала рабочего дня. Часовой пояс берётся из профиля.
- **Mila получила персональный стол** — 13 инструментов: план дня, свои задачи, заметки, напоминания, календарь. Задачи/заметки/напоминания создаются сразу (это личный черновик), календарь — только через двухшаговое подтверждение. Всё привязано к `user.id`: токен подтверждения одного аккаунта нельзя потратить в другом. Member получает тот же набор на своих данных.
- **Календарь на запись** — scope `calendar.events` вместо `calendar.readonly`; создание, перенос и отмена событий. Старое подключение продолжает работать на чтение и помечается `scopeStale` с кнопкой «Переподключить».
- **Напоминания** (`server/lib/reminders.js`) — «напомни в 15:00» реально срабатывает: тикер раз в 30 с кладёт напоминание во «Входящие» и шлёт push. Доставка идемпотентна.
- **Дайджест ERP** (`server/lib/erp-digest.js`) — просроченные заказы, склад готовой продукции, финансовая строка попадают в утренние алерты. Если инструмент не ответил, пишется «данных нет», а не ноль.
- **Вкладка «Персональное» перестроена** вокруг плана: расписание, «Дальше», алерты, панель Милы (звонок / «Разбор дня» / чат), напоминания. Переведено на RU/UZ/EN.

- **Утренний брифинг** (`server/lib/morning-brief.js`) — раз в местное утро собирает план, кладёт во «Входящие» и шлёт push. Срабатывает по часовому поясу каждого пользователя, ровно один раз в день; если слот пропущен больше чем на 3 часа, брифинг не шлётся вовсе (в 14:00 «доброе утро» — это шум). Есть кнопка «Прислать сейчас». Владелец (Creator) живёт в конфиге, а не в базе пользователей — перечисление учитывает это, иначе главный адресат остался бы без брифинга.
- **Рабочие часы в профиле** — начало и конец дня, обед, время брифинга и выключатель. Валидируются как HH:MM; перевёрнутый день откатывается к 09:00–18:00, мусорный ввод сохраняет прежнее значение, а не сбрасывает расписание.
- **Запись в ERP** — `create_erp_task` и `send_erp_notification` (двухшаговое подтверждение + только операторы, Member их не получает), плюс чтение `erp_late_orders` и `erp_list_employee_tasks`. При подтверждении проставляется собственный флаг `confirm` ERP, иначе ERP вернул бы только предпросмотр, а Мила отчиталась бы о несуществующей отправке.

**Задеплоено 2026-08-10**, коммит `33f5214`. Релизный гейт зелёный: 250 тестов на хосте и в образе, candidate health, production E2E.

**Google Calendar в проде настроен** (проверено 2026-08-12): `/api/personal/google/status`
отвечает `configured: true`, авторизационная ссылка уходит на правильный redirect
`https://agent.milanapremium.uz/api/personal/google/callback` со scope `calendar.events`.
Переменные называются `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` /
`GOOGLE_OAUTH_REDIRECT_URI` — не `GOOGLE_CLIENT_ID`, на этом легко ошибиться при проверке.
Строка про Google в конце `deploy.sh` печатается безусловно и ничего не диагностирует.
Осталось только одно действие владельца: нажать «Календарь» на вкладке «Персональное» и
подтвердить доступ в Google — `connected` пока `false`. Firebase настроен, push работает.

## 4. Приоритет и последовательность

Быстрые победы (первые 2 недели): Фаза 0 целиком + Фаза 1.1–1.2 (журнал в vault + чтение агентами) + Фаза 2.1 (Радар рынка — первая рутина).

Порядок дальше: 3 (лиды — деньги) → 5 (goal mode) → 2.2–2.4 → 4 (SEO) → 6 → 7 → 8.

**Блокеры от владельца** (уже зафиксированы в Marketing Playbook, теперь становятся критичными):
- составы тканей и размерные сетки (для SEO и карточек лидов);
- официальные соцаккаунты (для Muse);
- список реальных конкурентов (для Astros);
- есть ли розница; сезонность по месяцам.

## 5. Что сознательно не берём
- Пиксельный «питомец»-индикатор, музыкальный агент — не для B2B-продукта.
- Погоня за каждой новой моделью и «менеджер 15 моделей» — у нас управляемый стек, достаточно текущего переключения профилей.
- Мульти-сайтовый деплой SEO на 5 доменов — один milanapremium.uz, качество важнее.
- Его zip-дистрибуцию и всё, что относится к продаже комьюнити.
