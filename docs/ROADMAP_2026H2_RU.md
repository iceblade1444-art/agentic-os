## 2. Что делают сопоставимые продукты (август 2026)

**Персональные ассистенты с памятью** (Lindy, Arahi, Vellum-класс): постоянная память между сессиями, *проактивность* — сами присылают брифинги и поднимают релевантное из памяти без запроса, действия в сотнях интеграций. Наш разрыв: MILA помнит, но почти не *вспоминает сама*; проактивность ограничена утренним брифом.

**Open-source agent-OS** (OpenHands, AutoGPT, Khoj, Suna): парадигма «приложения — это инструменты агента»; Khoj индексирует Obsidian/файлы/почту для приватного поиска. Наш разрыв: поиска по собственному vault+переписке+ERP из одного места нет.

**ERP-копайлоты** (Business Central Copilot и класс): прогноз спроса, предсказание просрочки платежей, «жалоба по качеству → связанные заказы → черновик ответа за 5 минут вместо 40», приём заказа естественным языком. Наш разрыв: мы читаем состояние, но не анализируем тренды и не готовим документы.

**Командные AI** (Slack AI, Teams Copilot): recap канала «что я пропустил», суммаризация тредов, поиск с ответами по истории, итоги встреч с action items. Наш разрыв: в чате есть @mila, но нет recap'ов, поиска и встреч.

**Telegram-боты для бизнеса**: 80% рутинных запросов клиентов (статус заказа, каталог, цены), квалификация лидов прямо в чате, конверсия диалога 30–50% против 3–5% у форм. Для Узбекистана и СНГ Telegram — главный канал. Наш разрыв: наш бот пока только доставляет; клиентского бота нет вовсе. **Это самый большой недоиспользованный актив.**

**Голосовые агенты для телефона** (Retell, Vapi): входящие/исходящие звонки, follow-up пропущенных, CRM-логирование, 20–70 языков. Для нас — горизонт, не ближайшая фаза: PSTN-телефония — новая территория, а голосовая инфраструктура MILA уже занята живым диалогом.

## 3. План

Порядок — по бизнес-ценности для оптово-производственной компании, с учётом того, что инфраструктура под первые фазы **уже построена в августе**.

### Фаза A — MILA отвечает в Telegram ✅ СДЕЛАНО 2026-08-14
Сейчас бот отвечает «разговоры живут в приложении». Но привязка чат↔аккаунт уже есть и криптографически честная — значит, входящее сообщение от привязанного чата можно аутентифицировать и передать MILA с личным контекстом этого сотрудника.
1. Входящий текст от привязанного чата → `messenger-mila`-путь с аудиторией «owner» → ответ в тот же чат.
2. Работают личные инструменты: «что у меня сегодня», «напомни в 15:00», «запомни…», база знаний.
3. Непривязанный чат получает прежний вежливый отказ. Голосовые сообщения — фаза D (та же транскрипция).
*Эффект: MILA в кармане у каждого сотрудника без установки APK.*

### Фаза B — Клиентский Telegram-бот ✅ СДЕЛАНО 2026-08-14 (нужен токен от владельца)
**Отдельный бот** (не смешивать с внутренним): каталог и оптовые условия из базы знаний, статус заказа из ERP по номеру, приём заявки → квалификация (объём, страна, сеть) → карточка лида → менеджеру в канал «продажи» + в ERP. RU/UZ/EN.
Правила: цены и условия — только из базы знаний (страницы уже есть); чего нет — «уточню у менеджера», не выдумывать; передача человеку в один клик.
*Это та же «машина лидов» из старого плана, но входящая — дешевле и раньше исходящей.*

### Фаза C — Совещания: голос → протокол → задачи ✅ СДЕЛАНО 2026-08-14
У нас уже есть Speech Studio (своя транскрипция RU/UZ/KK/KY/EN) — большинство продуктов такого не имеют on-prem.
1. Кнопка «Записать совещание» (веб + телефон) → транскрипт через Speech Studio.
2. MILA делает протокол: решения, поручения с исполнителями, сроки → карточка в журнал дня.
3. «Разложи по задачам» — поручения становятся задачами (свои — сразу, чужие — через подтверждение).
*Закрывает то, за что платят Teams Copilot, нашими же компонентами.*

### Фаза D — ERP-аналитик ⚙️ 2026-08-14: недельный обзор ✅, дневные аномалии ✅, швейный отчёт ✅ (ждёт права в ERP); «жалоба→заказы» впереди
От «прочитать состояние» к «заметить и предложить»:
1. Недельный дайджест-рутина: динамика отгрузок, топ просрочек, склад по моделям, финансовая строка — сравнение с прошлой неделей, в Telegram владельцу.
2. Аномалии: резкое падение/рост, заказ близко к дедлайну — алерт в день обнаружения (механизм `erpAlerts` уже есть, расширить).
3. «Жалоба → связанные заказы → черновик ответа» — паттерн Business Central, у нас все данные для него есть.
4. Горизонт: прогноз спроса по сезонности (нужна история ERP ≥ года).

### Фаза E — Команда: «что я пропустил» ✅ СДЕЛАНО 2026-08-14 (recap; поиск с ответами — впереди)
1. Recap непрочитанного канала одной кнопкой (суммаризация уже освоена).
2. Поиск по переписке с ответом и ссылками на сообщения (`messenger.search` есть — добавить LLM-слой).
3. Ежедневный дайджест активных каналов — опционально, в Telegram.

### Фаза F — Проактивная память ⚙️ 2026-08-14: вечерний итог ✅, обязательства в утреннем брифе ✅; недельный обзор впереди
Разрыв с верхом рынка персональных ассистентов:
1. Вечерний итог дня (симметрия утреннему брифу): что сделано, что перенеслось, что завтра первым.
2. Проактивное напоминание обязательств из профиля: «обещали Шавкату ответить до пятницы».
3. Еженедельный обзор: незакрытое, повторяющееся, что автоматизировать рутиной.

### Фаза G — ⚙️ 2026-08-14: /learn ✅, реальные скиллы флота ✅ (4 шт, стоковые выключены)
- **Goal mode + судья** — осознанно отложен: встроенный оркестратор живёт без ключа (демо), а судить путь Hermes нельзя без опроса очереди AgentOS — тот же механизм, что нужен для «итоги рутин → журнал». Один механизм, построить один раз.
- **/learn** ✅: оператор описывает процесс — MILA собирает скилл по шаблону, показывает черновик, ставит после подтверждения; фидбек по имени обновляет скилл, а не плодит копию.
- **Радары** (рынок/конкуренты/контент) — после подтверждения блокеров владельцем.
- **SEO-петля** для milanapremium.uz (GSC уже упоминается в старом плане).

## 4. Блокеры владельца (без них встают фазы B и G-радары)
Те же, что в Marketing Playbook, критичность выросла:
1. **Составы тканей и размерные сетки** — без них клиентский бот отвечает «❔» на главные вопросы покупателей.
2. **Реальные конкуренты** — для радара.
3. **Официальные соцаккаунты** — для контент-аналитика.
4. Подтвердить подключение Google Calendar кнопкой на вкладке «Персональное» (сервер настроен, `connected` ждёт одного клика).

## 5. Чего сознательно НЕ делаем
- Погоня за каждой новой моделью и «галактики памяти» — украшательство.
- Массовые холодные рассылки без ручного одобрения — репутационный риск экспортёра.
- Свой PSTN-стек сейчас — дорого, рынок закрывается готовыми платформами, когда дозреем.
- Второй ассистент внутри Telegram-бота клиентов с доступом к внутренним данным — клиентский бот видит только базу знаний и статусы заказов, никогда — журнал, профили и переписку.

## 6. Рекомендованный старт
**A → B → C.** Фаза A — дни, потому что вся инфраструктура готова; B — главный источник новых денег; C — самая ощутимая экономия времени владельца. D–F параллелятся фоном по одной.
